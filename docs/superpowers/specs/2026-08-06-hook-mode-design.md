# `--hook-mode` — Design

Date: 2026-08-06
Status: Approved

## Purpose

Give `at-include` a second output shape purpose-built for injection into an
agent lifecycle hook (e.g. Codex's `SessionStart` hook), as the mechanism
behind a "local only" AGENTS.md strategy: a hand-authored `AGENTS.md` (or
`AGENTS.override.md`, gitignored) containing real `@tokens`, read
natively-but-literally by a tool that has no `@`-import support of its own.
The tool loads that file as-is — tokens included, unexpanded — and separately,
a lifecycle hook runs `at-include --hook-mode`, whose stdout is injected as
additional model context containing the same files, already expanded, framed
so the model knows it doesn't need to go look them up itself.

This is distinct from the existing "first class citizen" strategy, where
`AGENTS.md` is generated by normal `at-include` and checked in fully flattened
— there, `--hook-mode` would find nothing to expand (no tokens survive
generation) and simply be a no-op. `--hook-mode` only does useful work when
`AGENTS.md` itself still contains live `@tokens`, i.e. only in the "local
only" strategy.

## Behavior

### Invocation

A new boolean flag, `--hook-mode`, layered onto the existing flag set exactly
like `--check` is today — no subcommand, composes with `--src`/`--out`/`--root`
etc.

```sh
at-include --hook-mode
```

### Defaults, only when `--hook-mode` is set

- `--src` defaults to `AGENTS.md` (normal default: `AGENTS.src.md`).
- `--out` defaults to stdout (`-`) (normal default: `AGENTS.md`).
- Both remain overridable by explicitly passing `--src`/`--out`, exactly as
  today. An explicit `--out <file>` in hook mode still writes to that file
  rather than stdout — hook mode changes defaults, not what the flags mean.

### Preamble replaces the banner

Normal generation prepends `Banner(opts)` (the "this file is generated, do not
edit it" callout) to the flattened content via `Assemble`. Hook mode prepends
a different, fixed piece of text instead — call it the hook preamble. It is
**not** configurable (no flag analogous to `--marker-desc` controls it): there
is exactly one preamble, always the same text regardless of `opts`.

The preamble's fixed wording:

> We use `@path` import syntax in Markdown docs (e.g. `AGENTS.md`) to
> reference other files.
>
> Below, we've pre-expanded every `@import` found in `AGENTS.md` (recursively)
> so you don't need to look them up.
>
> If you encounter an `@path` reference in some other file that wasn't
> pre-expanded here, treat it as a pointer: go read that file yourself, since
> it won't be auto-resolved.

The preamble **always prints** in hook mode, regardless of whether the source
had any `@tokens` to expand — its job includes general standing guidance about
`@` syntax the model might encounter elsewhere, not only reporting what this
run expanded. (The one exception is the silent-empty case below, where nothing
prints at all.)

Per-file markers inside the expanded content are unchanged: the existing
`Contents of X (project instructions, checked into the codebase):` text (or
whatever `--marker-desc` overrides it to) is reused as-is. Only the
banner/preamble slot differs between the two modes; `Flatten`'s expansion
output itself does not change shape.

### Silent-empty only on missing source

Hook mode's stdout is consumed directly as model context, not read by a human
and not written to a file. There is no good way to surface an error there: an
error message would either be silently swallowed by whatever's consuming the
hook's stdout, or — worse, per Codex's hook contract — become something that
reads as an instruction *to the model* (e.g. exit code 2 becomes blocking
feedback shown to the model). Telling the model to "do something" about a
missing file is fraught and out of scope for what a hook can meaningfully ask.

So, in hook mode:

- If the source file does not exist, output is empty (no preamble, no error),
  exit 0. This applies **unconditionally** — whether `--src` was left at its
  hook-mode default (`AGENTS.md`) or explicitly passed by the caller pointing
  at a file that turns out not to exist. There is no "explicit --src means a
  real misconfiguration" carve-out; the failure mode (nothing useful to tell
  the model) is the same either way.
- If the source file exists but contains zero `@tokens` to expand, the
  preamble still prints (per above) — this is not the same case as a missing
  file, since the source read itself succeeded.

This makes `--hook-mode` safe to wire into a hook configuration
unconditionally, even in repos not using the "local only" strategy at all, or
in a state where `AGENTS.md` hasn't been created yet — it just contributes
nothing until there's something to contribute.

### Rejected combination: `--hook-mode` + `--check`

Usage error, exit 2, symmetric with the existing `--check` + `--src -`
rejection. `--check`'s entire purpose is comparing freshly generated output
against a stable on-disk file; hook mode has no such file — its output target
is stdout, transient, and mode-specific. Error message should explain the
reasoning, not just report "invalid combination" (matching the existing
`--check`/`--src -` error's style).

### `--list-imports`, `--version`, `--help`

Unaffected. `--hook-mode` only changes behavior for the default generate path;
combining it with `--list-imports` etc. is not a meaningful combination worth
special-casing — `--hook-mode` simply has no effect there (same treatment as
e.g. `--marker-desc` alongside `--list-imports` today).

## Architecture

`internal/cli.options` gains a `hookMode bool` field, set by a new
`--hook-mode` case in `parseArgs`. `parseArgs` cannot bake the
`AGENTS.md`-vs-`AGENTS.src.md` default into `o.src`'s initial zero value
(`o := options{src: defaultSrc, out: defaultOut}`), because flag order isn't
guaranteed and the hook-mode-aware default must be resolved once the full
argv has been parsed — so `Run` (or `resolveOptions`) applies the hook-mode
default for `o.src`/`o.out` **after** `parseArgs` returns, only when
`hookMode` is true and the corresponding flag was not explicitly set (i.e.
gated on `!o.srcSet`/`!o.outSet` the same way `--out`'s existing `outSet`
already distinguishes "defaulted" from "explicitly passed"; `--src` needs an
analogous `srcSet` bool added, since today it has none — `o.src` is always
non-empty and there is currently no way to tell "user typed the default value"
apart from "flag omitted", which hook-mode's default-switching now requires).

`internal/flatten.Options` gains a `HookMode bool` field (or equivalent),
threaded through the same way `OutIsStdout` is today. `runGenerate` branches on
it to decide which text to prepend:

```go
var assembled string
switch {
case fOpts.HookMode:
    assembled = flatten.Assemble(flatten.HookPreamble(), content)
case fOpts.Stdin != nil:
    assembled = assembleNoBanner(content)
default:
    assembled = flatten.Assemble(flatten.Banner(fOpts), content)
}
```

`flatten.HookPreamble()` is a new function alongside `flatten.Banner`,
returning the fixed preamble text as a plain string constant — it takes no
`Options` parameter (unlike `Banner`, which renders `--src`/`--out` names into
its text) since the preamble text never varies.

The silent-empty behavior is implemented as a check before `Flatten` is
called (or as a special case in `runGenerate`/a new `runHookMode`): in hook
mode, a missing source file short-circuits to writing nothing and returning
exit 0, rather than propagating `Flatten`'s `os.ReadFile` error through the
normal `fprintf(stderr, ...); return 1` path. This is the one place hook
mode's error handling diverges from every other mode — everywhere else,
`Flatten`'s error return is surfaced normally.

The `--hook-mode` + `--check` rejection is a new check in `Run`, alongside the
existing `--check` + `--src -` rejection, both before dispatching to
`runCheck`/`runGenerate`.

No changes to `internal/flatten/expand.go`, `scan.go`, or `Flatten`'s
recursive expansion semantics. The per-file marker text, inline-once/cycle
behavior, fence/code-span handling, and `--max-depth` all apply identically in
hook mode — only the top-level preamble and the missing-source error path
differ from normal generation.

## Non-goals

- No configurable preamble text (no `--hook-preamble-desc` or similar) — the
  wording is fixed by design, unlike `Banner`'s `--marker-desc` override.
- No new default `--max-depth` for hook mode. Recursive expansion depth is
  unlimited by default in hook mode exactly as it is today; "4 hops" was
  brainstorming-time phrasing for the preamble's wording, not a new cap.
- No subcommand form (`at-include hook`) — boolean flag only, consistent with
  how `--check` already layers onto the same flag set.
- No distinct default `--marker-desc` for hook mode's per-file blocks — they
  reuse the same text/override mechanism as normal generation.
- No error surfaced anywhere (stdout, stderr, or exit code) when the hook-mode
  source is missing — silent-empty, exit 0, unconditionally. (A source that
  exists but has zero `@tokens` is a different case and is not silent — see
  "Silent-empty only on missing source" above.)
